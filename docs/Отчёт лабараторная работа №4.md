# Отчёт о тестировании библиотеки geometric_lib

## 1. Цели и задачи тестирования

Цель: проверить через публичные функции, что библиотека вычисляет площадь и периметр согласно формулам, а недопустимые строковые входы не принимаются как корректные числовые данные.

Задачи:

- проверить правильность `area` и `perimeter` для круга, прямоугольника, квадрата и треугольника;
- проверить нулевые, целочисленные и вещественные значения;
- проверить отклонение строкового выражения, переданного вместо числового аргумента;
- обеспечить автоматический и воспроизводимый запуск тестов;
- зафиксировать фактическое поведение на проверяемых некорректных входах.

## 2. Описание тестируемого продукта

`geometric_lib` — набор модулей на Python, каждый из которых соответствует одной фигуре и содержит функции `area` (площадь) и `perimeter` (периметр).

Более подробная документация [тут](Documentation.md)

## 3. Область тестирования

Входит:

- все 8 функций четырёх модулей (круг, прямоугольник, квадрат, треугольник);
- корректность вычислений на нулевых, целочисленных и вещественных значениях;
- реакцию всех 8 функций на строковое арифметическое выражение вместо числового аргумента.

Не входит:

- производительность и нагрузка;

## 4. Стратегия тестирования

- Уровень: модульное тестирование публичных функций.
- Тип: функциональное тестирование методом серого ящика: тесты передают входные значения функциям и проверяют только наблюдаемые результаты или исключения, не проверяя внутреннюю реализацию.
- Техники: проверки по формулам, нулевые/целые/вещественные входы и некорректная строка `"1 + 1"`; `subTest` для таблиц сценариев; `assertAlmostEqual` для значений с плавающей точкой.
- Проверка безопасности ограничена базовой обработкой строкового ввода: выражение, переданное строкой, должно быть отклонено как неверный числовой аргумент, а не интерпретировано как код. Это не полноценный аудит безопасности и не нагрузочное тестирование.
- Инструмент: стандартный модуль `unittest`.

## 5. Критерии приёмки

- все 8 функциональных сценариев по формулам корректны для каждой функции на нулевом, целочисленном и вещественном примерах (точность `assertAlmostEqual` — 7 знаков);
- все 8 проверок строкового ввода отклоняют выражение `TypeError`;
- результаты всех сценариев зафиксированы; провал любой проверки безопасности считается дефектом обработки входных данных;
- покрытие кода, иные некорректные типы и полноценный аудит безопасности не входят в критерии этой проверки.

## 6. Ожидаемые результаты

- набор автоматических тестов;
- протокол запуска: число выполненных, пройденных и упавших тестов;
- описание обнаруженных дефектов с входными данными и наблюдаемым результатом;
- метрики: число тестовых методов, число успешных и упавших методов;
- фактическая публикация тестов и коммит в общедоступном репозитории.

## 7. Актуальные результаты тестирования

Команда запуска из корня проекта: `python3 -m unittest discover -s tests -v`.

| Проверка | Результат |
| --- | --- |
| Модульные тестовые методы | 9 выполнено: 8 пройдены, 1 завершился ошибкой |
| Проверки формул | Все 24 сценария (3 для каждой из 8 функций) пройдены |
| Строковый ввод `"1 + 1"` | 6 функций выбросили `TypeError`; `rectangle.area` вернула строку `'1 + 11 + 11 + 1'`, `square.perimeter` — `'1 + 11 + 11 + 11 + 1'` |
| Итог запуска | `Ran 9 tests ... FAILED (failures=2)` — две неуспешные проверки являются subTest внутри одного метода |

Проверка строкового ввода завершилась ошибкой: 2 из 8 subTest не получили ожидаемый `TypeError`. `rectangle.area` вернула строку `'1 + 11 + 11 + 1'`, а `square.perimeter` — `'1 + 11 + 11 + 11 + 1'`. Остальные шесть функций выбросили `TypeError`. Покрытие кода не измерялось.

## 8. Выводы из результатов тестирования

Все функции прошли 24 проверки вычислений на нулевых, целочисленных и вещественных входных данных. Проверка строкового ввода выявила различие в поведении: шесть функций выбрасывают `TypeError`, но `rectangle.area` и `square.perimeter` возвращают строковые значения для аргумента `"1 + 1"`. Рекомендуется определить единое требование к типам аргументов и при необходимости добавить валидацию числового ввода. Тестирование не является полным аудитом безопасности; покрытие кода не измерялось.
