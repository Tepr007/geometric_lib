# Отчёт о тестировании библиотеки geometric_lib

## 1. Цели и задачи тестирования

Цель тестирования — проверить результаты публичных функций вычисления площади и периметра для круга, квадрата, прямоугольника и треугольника на типовых, нулевых, отрицательных и граничных числовых значениях, а также проверить реакцию на строковые аргументы.

Задачи:

- проверить все функции `area` и `perimeter` четырёх модулей;
- сопоставить результаты с ожидаемыми значениями по формулам;
- проверить целые и вещественные числа, нулевые и отрицательные значения;
- проверить большие значения порядка `10**100`;
- проверить, что строковые значения вызывают `TypeError`.

## 2. Описание тестируемого продукта

`geometric_lib` — набор модулей Python для вычисления площади и периметра круга, квадрата, прямоугольника и треугольника. Каждый модуль предоставляет функции `area` и `perimeter`.

Дополнительная документация находится [тут](Documentation.md).

## 3. Область тестирования

Проверяются все 8 публичных функций:

- `circle.area` и `circle.perimeter`;
- `square.area` и `square.perimeter`;
- `rectangle.area` и `rectangle.perimeter`;
- `triangle.area` и `triangle.perimeter`.

Для каждой функции предусмотрены стандартные числовые примеры, нулевые значения, отрицательные значения, большие числа и строковые аргументы. Для функций с несколькими параметрами проверяются разные сочетания значений аргументов.

Не входят в область тестирования производительность, нагрузка, покрытие кода и полноценный аудит безопасности.

## 4. Стратегия тестирования

- Уровень: модульное тестирование.
- Тип: функциональные проверки наблюдаемого результата или исключения.
- Инструмент: стандартный модуль `unittest`.
- Сценарии сгруппированы по категориям `standard_cases`, `zero_cases`, `negative_cases`, `string_cases` и `edge_cases`; для диагностики используется `subTest`.
- Для сравнения результатов применяется `assertAlmostEqual`; в больших числовых сценариях круга — `math.isclose`.
- Строковые проверки ожидают `TypeError`. Отрицательные числовые аргументы не считаются ошибочными: тесты сверяют результат с арифметикой реализованных формул.

## 5. Критерии приёмки

- результаты числовых сценариев соответствуют ожидаемым значениям;
- каждая строковая проверка завершается ожидаемым `TypeError`;
- все тесты запускаются командой `python3 -m unittest discover -s tests -v`.

## 6. Состав тестового набора

Набор содержит 8 тестовых методов: по одному для площади и периметра каждой фигуры. В методах сгруппировано 107 проверочных сценариев:

| Фигура | Сценарии с числовыми значениями | Строковые сценарии | Всего |
| --- | ---: | ---: | ---: |
| Круг | 20 | 6 | 26 |
| Квадрат | 20 | 6 | 26 |
| Прямоугольник | 22 | 6 | 28 |
| Треугольник | 21 | 6 | 27 |
| **Итого** | **83** | **24** | **107** |

Числовые сценарии включают типовые, нулевые, отрицательные и граничные значения.

## 7. Результаты тестирования

Команда запуска из корня проекта:

```text
python3 -m unittest discover -s tests -v
```

Фактический результат последнего запуска:

| Показатель | Результат |
| --- | --- |
| Тестовые методы | 8 выполнено |
| Успешные проверочные сценарии | 101 |
| Неуспешные проверочные сценарии | 6 |
| Итог | `FAILED (failures=6)` |

Ошибки сгруппированы в двух тестовых методах:

| Функция | Сценарии | Наблюдаемый результат |
| --- | --- | --- |
| `rectangle.area` | 3 строковых аргумента (`"0"`, `"2 + 2"`, `"1.5"`) | `TypeError` не возникает |
| `square.perimeter` | 3 строковых аргумента (`"0"`, `"2 + 2"`, `"1.5"`) | `TypeError` не возникает |

Остальные 101 сценарий пройден. В частности, тесты площади треугольника, включая два граничных случая с аргументами порядка `10**100`, проходят. Строковые аргументы во всех проверках, кроме `rectangle.area` и `square.perimeter`, вызывают ожидаемый `TypeError`.

## 8. Выводы

Расширенный набор проверяет все функции на нескольких категориях числовых данных и на строковых аргументах. После исправления ожидаемых значений для граничных случаев `triangle.area` соответствующие проверки проходят. Оставшиеся 6 ошибок относятся к строковым аргументам: `rectangle.area` и `square.perimeter` не выбрасывают ожидаемый `TypeError`. До достижения критериев приёмки необходимо согласовать и при необходимости реализовать единое поведение для таких входных данных.
